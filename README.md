# 優品360 海報工作台

以活動表格或手動選品建立海報，提供素材索引、商品組合、分步校對與 PNG 預覽下載。提供管理員登入及活動版本留痕；商品庫 API、POS 自動核對與多人分級審批尚未接入。

## Docker 部署：6695

在已啟動 Docker Desktop／Docker Engine 且能下載依賴的環境執行：

```sh
python3 scripts/setup_admin.py
docker compose up -d --build
```

訪問 http://localhost:6695 。其他電腦使用伺服器 IP 及 6695 端口。

- `web`：Nginx 提供前端，主機 6695 → 容器 80；/api 代理到後端。
- `cutout`：FastAPI，處理 Excel／CSV 解析及 rembg CPU 自動抠圖；不直接開放主機端口。
- `cutout-models`：模型快取資料卷。第一次抠圖需要下載 U2Net 模型，耗時可能較長。
- `poster-data`：活動、版本與圖片的持久資料卷。
- 容器健康檢查、日誌輪替及自動重啟已配置。/api/health 的 model_loaded 表示模型是否已載入；HTTP 健康不代表模型已下載完成。

```sh
docker compose ps
docker compose logs --tail=100 cutout
curl --fail http://localhost:6695/healthz
curl --fail http://localhost:6695/api/health
# 修改程式後重新構建
docker compose up -d --build
# 停止容器（不刪除模型卷）
docker compose down
```

## 不使用 Docker

Node.js 22、Python 3.11（與 Docker 一致）。安裝固定 Fabric.js 依賴後，postinstall 會複製瀏覽器模組到 vendor 目錄：

```sh
npm install --registry=https://registry.npmjs.org
npm start
```

訪問 http://127.0.0.1:8765 。單純 Python 靜態服務不提供 /api，現在登入、Excel 解析、自動抠圖及伺服器存檔均需完整 Docker 服務或同源 API 代理。不要用 file:// 開啟頁面。

## 分步生成

1. **選模板**：選擇底圖、填寫活動日期與門店，或直接匯入活動 Excel。
2. **加商品**：選圖、填價格與件數；一鍵並排／前後錯落。尺寸、陰影和組內微調收在進階設定。商品清單、工具欄及 Delete 鍵均可刪除海報元素，保留素材庫原圖。
3. **確認下載**：自動產生預覽，查看檢查結果，填確認人並勾選確認。完整版本及 PNG 成功存入伺服器後才能下載。

每次只顯示當前步驟。前置資料未完成時返回對應步驟。修改內容會撤銷當前確認，歷史已確認版本保持不變。生成期間內容被修改時結果作廢。輸出保留待核對標記；校對狀態不代表已核對門店 POS 價格。

## 活動資料與圖片追溯

- 草稿停止操作約 2 秒後自動同步伺服器，同時保留瀏覽器 IndexedDB 快取。頂部區分本機保存與伺服器保存狀態；服務失敗時會明確顯示未同步。
- 活動名稱、日期、門店、商品索引、全部商品圖片、自訂底圖、使用的內建底圖、價格／件數、布局、匯入表格的行號及來源價格快照一同存檔。尚不保存原始 Excel 檔案。
- 確認另存含最終 PNG 的版本，記錄伺服器 UTC 時間、填寫的確認人、存檔序號、草稿修訂號及 SHA-256。相同請求重試不重複建檔；圖片按內容雜湊去重。
- 頂部「活動存檔」列出歷史版本，可查看已存海報、下載原 PNG／含圖片 JSON、從歷史版本繼續編輯。後續修改另存，不覆寫歷史版本；不提供覆寫歷史版本；可在活動存檔明確刪除整個活動及其全部版本。
- 新版本確認人由已驗證的管理員帳號記錄；尚無正式多人分級審批。雜湊用於核對內容，不是數位簽章或防資料庫管理員修改的審計保證。
- `/api/archives` 提供保存及分頁查詢；`/api/archives/{id}/project` 還原資料與圖片，`/api/archives/{id}/poster` 取回當時 PNG。
- SQLite 檔案及圖片 BLOB 保存在 `poster-data` Docker 資料卷的 `/data/archives.sqlite3`，普通容器重建／重啟不會刪除。請備份資料卷；`docker compose down -v` 會刪除資料。備份運行中的資料庫請使用 SQLite backup API，或停服務後完整備份資料卷（含 WAL）。
- 增量存檔資料上限 2 MB，圖片分開上傳，每張商品圖 12 MB、生成 PNG 24 MB；舊版完整存檔接口保留 180 MB 上限。不是只保存原圖片的本機路徑，因此更換電腦仍能讀取同一伺服器的活動存檔。

## 活動 Excel / CSV

點擊「上傳 Excel / CSV」。支援 .xlsx 或 UTF-8 .csv；.xls 需先另存。上限 5 MB，一行一個商品、一張海報最多 12 行商品；更多商品需分批，不會靜默截斷。

首行欄位（簡繁中文均支援）：

| 欄位 | 規則 |
| --- | --- |
| 活動名稱 | 必填；同一檔案一致 |
| 商品名稱 | 必填 |
| 商品編號 / SKU / 條碼 | 選填；使用文字格式，保留前導零 |
| 規格 | 選填，發布前人工確認 |
| 優惠總價 / 活動價 | 大於零、最多兩位小數；無貨幣符號 |
| 優惠件數 | 1–99 整數；總價對應的購買件數 |
| 開始日期、結束日期 | Excel 日期或 YYYY-MM-DD；同一檔案一致 |
| 適用門店 | 必填；同一檔案一致 |

例如總價 33、件數 2，海報顯示 $33 / 2件，不會當作每件 $33。多工作表時把目標命名為「活動商品」或「活动商品」。公式必須先貼上數值，避免依賴過期快取。不同活動／日期／門店不能混為一張海報。

匹配優先使用提供的商品編號，沒有編號才查名稱。唯一完整匹配自動關聯；同名多角度、部分匹配、缺圖都要在預覽中選圖。沒有圖片時取消匯入，先上傳並補充索引，再重新匯入。确认后替換目前活動與畫布，原素材庫保留；已有海報時再次確認覆寫。

匯入後保留檔名、表格行號及原始價格／件數快照。海報价格／件數改動後顯示與來源不一致提示，必須重新校對。暫不支持會員條件、積分換購及其他複雜促銷導入，檢出這類欄位會阻止套用，避免忽略條件而宣傳一般售價；其他未知欄位提示不會套用。

## 素材與文件索引

內建五張提供的商品照片（兩張秋田小町米、三張 Indomie 不同角度），由 assets/catalog.json 管理。啟動時補入缺少的樣品，不覆寫已編輯的索引。樣品 SKU 留空，未將檔名冒充正式商品編號。

商品下拉選擇名稱和角度。也可按名稱、SKU、原始檔名、別名搜尋，支援全半形及大小寫規範化；不猜測數字檔名的商品身份。使用「編輯索引」補充資料，同名多圖要求選擇。商品圖片最多 100 張，自訂底圖最多 20 張。PNG／JPG／WebP 單張最多 12 MB。

圖片、索引、草稿及流程記錄在本瀏覽器 IndexedDB 保留快取，並自動同步伺服器版本庫。只有已成功同步的版本能跨電腦讀取；清除瀏覽器前請確認頂部伺服器存檔成功。JSON 備份會帶上圖片。更換主機名稱或從 8765 改為 6695 是不同 origin，請先匯出備份再匯入。

## Fabric.js 編輯及商品組合

已增加 src/fabric-editor.js，接入 Fabric.js 6.7.1 的 Canvas、Group、FabricImage、Textbox 與 StaticCanvas。Docker 構建會將套件複製到本機 vendor 目錄，頁面不依賴外部 CDN。若本地未安裝，明確顯示「相容模式：Fabric 尚未載入」，使用旧 Canvas 功能。

- 拖動及縮放整個商品組件，價格與圖片共同移動。
- 框選或按 Shift 多選商品，使用「合併所選商品」。
- 右側「圖片展示」複製同款或從素材庫加入另一件，每組最多六張。
- 「並排」「前後錯落」，或選中組內圖片後調整相對位置、寬高及前移／後移。
- 「替換選中圖片」可使用抠圖後的新素材；保留組件位置和促銷資料。
- 合併兩個商品組件時保留主組名稱／規格、累計件數並清空價格，要求重新確認。
- 單純添加圖片不自動更改促銷件數，避免把不同角度／口味展示誤當成購買數量。
- 名稱、價格等透過屬性面板修改，保持與業務資料綁定。文字定位支援搜尋並跳轉編輯。
- 編輯與導出使用同一套 Fabric 場景建立函數，下載已生成 Blob。

## 自動抠圖

商品卡片「自動抠圖」呼叫 POST /api/cutout-jobs 提交持久化任務，再查詢進度與結果，輸出裁去全透明留白的透明 PNG，保留半透明包裝邊缘。完成結果自動保存為待確認素材，保留原圖；從商品組合發起時，確認後直接替換組內對應圖片。抠圖請求在記憶體處理；確認保存為素材後，隨活動快照持久存入伺服器。

任務資料及結果存於同一 `poster-data` 卷內的 `cutout-jobs.sqlite3`，刷新後由瀏覽器已存任務編號恢復。可點「查看抠圖任務 / 恢復結果」重連；服務重啟後首次提交或查詢會重新排入中斷任務。佇列最多 12 張，單執行緒逐張處理；相同原圖命中成功結果時直接復用。進度區分排隊、載入模型、推理與保存。原 `/api/remove-background` 保留相容用途。

首次下載模型、CPU 推理與大圖預處理可能耗時；輸入推理前長邊限制為 1800px，減少大型原圖的記憶體及前後處理成本，不代表已量測推理加速。原圖保留，抠圖輸出解析度可能降低。任務佇列目前配合 Docker 的單一 Uvicorn worker；不可直接增加多程序 worker。

透明包裝、反光及既有陰影可能不準，需人工核對產品邊緣及文字。這不是生成式重畫，不會主動重新生成包裝文字；但模型仍可能誤刪前景。人工修邊及校色尚未實現。

## 商品 API 對接

UploadProductProvider 提供 list(query)、get(id)、resolve(query)、updateMetadata(id, metadata)。後續替換為 API 資料供應器時，仍需實作認證、分頁、錯誤處理、跨域圖片及版本快照。商品／資產 ID 與 SKU 分開，SKU 保留字串。活動價應由促銷資料來源提供，不應以商品主檔一般售價代替。

## 邊界與驗證

已提供單一管理員登入；尚未提供多人審批、商品庫／POS 同步、門店發布及撤換閉環；亦無印刷 PDF、CMYK、旋轉、撤銷／重做、OCR、積分換購元件或人工修邊。兩款歷史底圖仍含旧活動條款，使用前需核對條款。

本次已通過 JavaScript 語法檢查、23 項 JavaScript 測試、21 項 Python 圖片驗證／匯入／存檔接口測試，以及 Compose 配置校驗。推理接口回傳測試使用替身，未运行真實模型；Excel 測試覆蓋行校驗、CSV、無效 XLSX，未以實際活動 XLSX 完成端到端驗證。

當前執行環境不能解析 npm 倉庫、無權連接 Docker socket，且預覽瀏覽器不可用。因此 Fabric 安裝與瀏覽器互動、Docker 構建、模型下載及樣品抠圖效果尚未驗證。直接依賴固定版本；因網路限制尚未生成 npm 完整傳遞依賴 lockfile。

```sh
npm run check
npm test
python3 -m unittest discover -s backend -p 'test_*.py' -v
```

Python 測試需 fastapi、Pillow、openpyxl 和 httpx；真實抠圖額外需要 requirements.txt 的 rembg/ONNX Runtime。


## 多尺寸與底圖調整

第一步支援 A4、A3、435 × 620 mm、1080 方形、手機直版、1920 橫版，以及自訂 px/mm + 72–600 DPI。點「套用尺寸」後保留圖層，按比例調整位置及尺寸；可在第二步自動排列。輸出限制每邊 200–8192px、總面積 4000 萬像素、寬高比 0.4–2.5。PNG 寫入 pHYs 解析度資訊，毫米以像素四捨五入換算；不提供 CMYK 或出血 PDF。

選用圖片底圖時，第二步「調整底圖」可拖動位置；Fabric 模式可拖四角縮放，相容模式以滑桿縮放。可選完整顯示、鋪滿、還原，默認完整顯示以免裁掉底圖條款。清爽版為程式繪製的版式，不是可拖動的圖片。修改會撤銷確認；尺寸、底圖位置、DPI 與 PNG 隨活動版本一起存檔。歷史檔案未填尺寸時沿用 1800 × 2560。

清晰度檢查會提示商品圖的輸出放大倍率。模型抠圖或原始照片解析度不足時，選擇 300 DPI 不會增加原圖細節。多尺寸與拖拽的瀏覽器實際效果仍待驗證。

整張海報顯示縮放：在畫布上方調整 40–180%，底圖、商品與文字共同放大縮小，僅影響螢幕顯示。輸出紙張尺寸在第一步設定；套用新尺寸時使用同一個等比例變換調整現有元素與已手動定位的底圖。底圖編輯預設鎖定位置，只有點「移動底圖」後才能平移，避免誤拖。原生拖動會在按鍵鬆開、失去捕獲、失去焦點時結束；Fabric 中斷手勢使用其公開 endCurrentTransform 方法。


### 畫布尺寸操作修正

「調整海報尺寸」現在調整整張黃色畫布，而非背景圖片圖層。點擊會直接展開寬、高、px/mm、DPI 設定；可拖動畫布右下角 ↘ 手柄預覽尺寸，松開後套用。勾選保持比例時整版等比例縮放，取消後可變更寬高比。按「按底圖比例適配」會以底圖比例更改畫布，清除舊的背景獨立偏移和縮放。這些操作同步修改 PNG 輸出尺寸並撤销舊確認。原底圖移動選框入口已移除，畫布縮放手柄在相容模式也可用。尺寸按鈕事件在編輯器與樣品載入前綁定。

畫布尺寸調整行為：預設只改變頁面尺寸與底圖適配，不改動商品及文字的座標、寬高、字號或組合關係。縮小畫布造成越界時提示並阻止確認，不自動移動圖層；如需重新排版，使用獨立的「自動排列」操作。

### 自動商品排列

新增商品及 Excel 匯入時，根據實際圖片寬高、商品數量與海報可用區域，自動選擇網格並設定商品尺寸；單件商品限制展示大小，會員模板保留八格位置。畫布上的「自動排列」可重新整理所有商品，會覆蓋商品手動位置與尺寸；不修改名稱、規格、價格、優惠件數或独立文字。自動排列是按圖片佔用面積評分的規則式排版，複雜自訂底圖仍需人工確認。

商品組內兩張圖片預設前後錯落，已有錯落組合在自動排列時保持錯落模式；其餘組合按圖片比例選擇左右或上下排列並保留間距。加入、複製、替換圖片後自動套用；「前後錯落」仍可切換前後順序。點擊可見縮圖選中單張後，按「刪除所選圖片」或 Delete 可移除組內圖片；刪除最後一張時移除整個商品組件。移除組內圖片不變更優惠件數及價格，仍須重新校對。圖片始終等比例縮放，預覽和匯出共用圖片座標及文字留白規則；圖片尺寸資訊與組合位置會隨活動版本保存。


## 管理員登入與 Excel 模板下載

部署前執行 `python3 scripts/setup_admin.py`，在專案 `.env` 建立帳號 `admin` 和隨機初始密碼。檔案權限為 600，已排除版本控制與前端鏡像；密碼不會列印到部署日誌。在 `.env` 查看 `ADMIN_PASSWORD`，或在首次啟用帳號前改成至少 6 字元的密碼。首次登入初始化後，密碼雜湊與登入會話保存於 `poster-data` 的 `auth.sqlite3`；變更 `.env` 後重新建立服務，啟動時會同步管理員密碼並撤銷舊登入會話。

登入採用 scrypt 密碼雜湊、HttpOnly / SameSite=Strict Cookie、8 小時有效期及伺服器端退出撤銷。登入失敗 5 次後，同一來源暫停嘗試 15 分鐘。Nginx 保護工作台及業務素材，後端獨立保護業務 API；健康檢查和登入頁可匿名存取。以 HTTPS 部署時設定 `COOKIE_SECURE=true`。目前是單一管理員，不包含多人角色分權或 SSO。

新存檔記錄登入帳號；確認人由伺服器設定，不能透過表單冒填。歷史確認版本保持原樣並標記為未驗證身份。

原 Excel 上傳入口旁新增「下載 Excel 模板」。模板保留現行 9 個欄位、命名為「活動商品」的工作表及一行示例；商品編號預設文字格式，保留前導 0。請替換示例資料後上傳。未修改現有 Excel 上傳或商品匹配流程。

## 圖片標識

第二步工具列「＋ 標識」可上傳 PNG / JPG / WebP（每張最多 12 MB，最多 50 張素材），上傳後直接加入海報；建議透明底 PNG。彈窗中可重用已上傳標識，也保留新增文字標識入口。圖片等比例顯示，支援拖動、尺寸調整、複製、前後層級及刪除；刪除海報上的標識不刪除素材。標識圖片及位置隨活動存檔與 JSON 備份保存，不參與商品自動排列。Fabric 與相容畫布均支援預覽和 PNG 匯出。


## 維護與回歸修正

內建底圖歷史快照只在恢復會員／促銷模板時轉為自訂底圖，之後清除快照欄位；自訂底圖存檔不沿用舊快照。清爽模板的頁眉及頁尾按畫布尺寸排版，並為匯出狀態條留出空間。無工作表 dimension 或錯誤範圍的 XLSX 按實際內容讀取，忽略僅有格式的空白行及尾部空白單元格，限制 200 個非空行／40 個內容欄位位置，另設 10,000 行掃描上限；錯誤保留工作表原始行號，日期錯誤使用中文提示。

抠圖任務是快取，已結束任務預設最多保留 7 天／200 個／512 MB 結果資料（任一上限先到即清理最舊任務）。成功或失敗即釋放任務原圖副本；排隊與處理中的任务不清理。服務啟動、提交、處理完成及工作執行緒每小時清理；啟動和每小時維護會收回大量空閒 SQLite 頁面。`archives.sqlite3` 的已存活動圖片不受影響。被清理且尚未存檔的結果需重新抠圖。

登入鎖定從第 5 次失敗起計 15 分鐘。海報圖片 API 統一採用 no-store。自動存檔已採用圖片增量同步，後續只傳送活動資料及圖片引用；活動資料仍是完整版本快照，未使用 JSON Patch。


## 增量存檔協議

前端以圖片實際位元組計算 SHA-256，透過 `POST /api/archive-assets/check` 確認伺服器缺少的圖片，再以 `PUT /api/archive-assets/{hash}` 上傳缺少的二進位檔案（同時最多 2 張）。商品、標識、底圖、內建底圖快照及生成海報都使用同一機制；同一圖片跨版本或跨活動重用。HTTP 環境不支援 Web Crypto 時有 SHA-256 相容實作。重新整理會再次檢查伺服器，不依賴「曾上傳」的本機標記。

`POST /api/archives/incremental` 只提交活動快照和 `{assetHash}` 圖片引用，不內嵌 base64。編輯價格、文字或位置不重新上傳圖片。保存之前校驗全部引用、圖片大小及海報尺寸；缺圖不提交不完整版本，前端可重新同步後重試一次。伺服器以交易保存版本並將素材轉為已引用；重試相同快照不產生重複版本。自動存檔會略過排隊期間已被新編輯取代的草稿。

已存在的 SQLite assets / versions 與舊版完整存檔接口保持相容；舊素材首次引用時補充尺寸索引，不重寫歷史版本。歷史恢復及完整 JSON 備份仍返回內嵌圖片，下載體積未改為增量；瀏覽器本機草稿仍保存完整資料。

已上傳但尚未成功存檔的素材暫存 7 天，暫存總量上限 3 GiB；啟動及圖片清單檢查時清理過期暫存。任何成功版本引用的圖片都不會被這項清理刪除。首次保存大量新圖片仍需傳送其全部內容，但分為獨立請求，不再受單次 180 MB 全量存檔限制。


### 多分頁草稿保護

本機草稿以獨立儲存版本號，在同一個 IndexedDB 讀寫交易內比較並更新。另一分頁先保存後，舊分頁會拒絕覆寫並持續提示衝突；本頁內容保留於記憶體，可點「匯出專案備份」，再重新載入最新草稿。系統不自動合併兩份修改。伺服器仍保留各次成功存檔的歷史版本；伺服器存檔成功不代表本機衝突已解決。部署後請重新載入所有已開啟的舊版分頁，讓各頁使用相同的版本檢查機制。

## 至優價模板與印刷版（2026-10）

第一步選擇「至優價 · 3＋3＋4」，填寫活動日期和門店。可設定每行商品數及行高比例，並編輯底部活動說明。「載入樣稿商品示例」載入提供 PDF 的商品素材和歷史價格，替換目前畫布；日期、門店清空，必須重新核對。這項操作可撤銷。品牌標題和 Logo 為鎖定素材，舊樣稿的日期、門店數量及條款沒有作為本次活動內容沿用。

選中商品後，可選「至優價 · 文案左／價格右」排版：

- 大整數、小小數與貨幣符號分開排版；多件優惠同時顯示平均每件價格和紅底白字總價條。平均價可四捨五入至整元、一位或兩位小數；優惠總價和件數保持原值。
- 原價、原價上限、刪除線，以及新／熱賣／精選角標。Excel 模板增加這五個選填欄位，原有九欄格式仍可匯入。
- 「獨立調整圖片、文案與價格區域」可用百分比調整圖片、名稱、規格、原價、價格的位置和寬高；名稱、規格、原價可設字體類型、字號、粗體、顏色、行距及對齊。長文案自動換行及縮小以避免溢出；名稱可手動換行。
- 價格區域與圖片區域獨立，放大價格不會縮小商品圖片。商品、圖片組合及樣式可存檔、還原和 JSON 備份。
- 鎖定位置／尺寸、Shift 多選對齊及等距排列、移動吸附與參考線；撤銷／重做最近 30 次編輯，快捷鍵 Command/Ctrl+Z、Command/Ctrl+Shift+Z。撤銷會清除原確認狀態，需重新生成和確認。

第三步可選「校對版」或「印刷版」。印刷版不包含底部待核對提示，但仍須生成預覽、勾選確認並成功存檔後下載。PNG 與 PDF 使用同一張已確認圖像。PDF 是 RGB 高解析度圖像 PDF，按設定 DPI 換算物理紙張尺寸；可選 3 mm 邊緣延展出血、裁切線與 TrimBox/BleedBox。不是向量文字 PDF、CMYK 或 PDF/X；印廠要求這些格式時需另行轉換。字體目前使用瀏覽器系統字體；輸出已轉成圖片，不依賴收件端安裝字體。

新模板沒有內嵌原 PDF 的舊活動條款。品牌頭尾圖片隨伺服器版本以雜湊素材保存，恢復歷史版本時使用原素材。切換 A3／A4 後按「套用分行布局」重排，並檢查清晰度、安全邊距、日期及優惠條件。

驗證包含價格取整、3＋3＋4 布局、原價／區域校驗、撤銷重做、備份往返、Excel 選填欄位和後端確認存檔。`output/evaluation/retail-preview.png` 及 `output/pdf/retail-preview-a3.pdf` 是離線共享布局預覽（不是瀏覽器截圖）。瀏覽器互動尚需部署後驗證。

## 刪除活動

在「活動存檔」開啟任一版本，點「刪除此活動（所有版本）」並確認，會刪除該活動的全部草稿、歷史版本及已確認海報。此操作不可復原；需要保留時先下載備份。其他活動及本機素材庫不受影響。若刪除的是目前正在編輯的活動，工作台會切換到新空白項目，保留素材庫。

刪除接口需要登入並檢查同源請求。伺服器保留活動刪除記錄，阻止舊分頁的自動保存重建已刪除活動（HTTP 410）；舊分頁可新建項目繼續使用。其他活動共用圖片保留，無引用圖片進入既有 7 天暫存清理。沒有執行任何現存活動刪除；測試使用隔離資料庫。

## 素材刪除與統一參數頁

素材庫每張商品卡可點「刪除素材」。確認後移除目前項目的素材及畫布引用；空商品組會刪除，組合內其他圖片保留，價格及優惠件數不自動改動。歷史版本和其他項目不受影響；可撤銷。已刪除的內建樣品記錄於專案，刷新時不再自動補入；新建並沿用素材庫時也保留這份記錄。

右側「編輯內容」下拉框切換商品圖片、商品名稱、規格、原價、促銷價格，只顯示該項的內容、位置及樣式；點擊畫布文字或圖片亦會切換對應頁。整組排版、角標及層級收在獨立折疊設定中。

商品文字及價格字號支援 1–1000。預設自動縮字以符合區域；關閉後採用指定字號，超出區域會在檢查區提示，需調整區域大小以避免重疊。

手動修改商品名稱、規格、原價、促銷價格或獨立文字的字號時，會自動關閉該項的縮字設定，按指定字號顯示；可再勾選自動縮字。參數面板顯示固定字號或自動排版字號。舊草稿保留原有縮字行為，重新修改字號即切換為固定模式。

### 上传底图、提取旧商品与替换商品

第一步「上传底图（图片／PDF）」支持 PNG / JPG / WebP（最多 12 MB）和 PDF（最多 30 MB，可选 1–200 页中的一页）。上传时先保存当前活动，再以该底图自动建立独立新活动，停留在活动资料页。保留素材库，不带入原活动的画布商品、日期或报价；填写活动名称、日期和门店后，点击「下一步：加商品」；商品框选在加商品页进行。新增商品不会自动重排已有商品，手动「自动排列」仍可用。

在「加商品」工具栏点击「框选 PDF／底图商品」，直接在主画布拖曳框选完整旧商品区域（图片、名称、规格、价格），选择遮盖颜色或从底图取色。若需要沿用旧商品图片，点击「框选旧商品图片」，在未遮盖的原底图上只框包装图片，再点「提取图片并套入此区域」。图片按原图像素裁剪，最长边不超过 1800 像素，存入素材库，同时建立可编辑商品；手动框选的裁剪图不运行 OCR，名称、规格和价格需自行填写；PDF 自动导入的识别流程见下节。可改选素材库图片或上传新图片来替换商品。

点「套用并进入加商品」后，可选择对最后提取的商品启动现有抠图流程；确认抠图结果才会替换商品图片，原裁剪素材保留。其余图片可从素材库点「自动抠图」，或在商品图片参数页使用「去背景并优化组合」。可继续修改图片、名称、规格、价格、位置、颜色和字号。

底图与旧海报统一使用同一个上传入口，不再区分两套流程。上传即自动新建，无需返回点击「建立新的海报」。若要复用已经编辑好的套版，可在编辑页工具栏点击「沿用套版建立新活动」。套版的遮盖区、提取图片和商品图层支持本机草稿、活动存档、JSON 备份以及 PNG/PDF 输出。以后可用「沿用套版建立新活动」复用已框选区域。替换商品保留位置和样式，清空旧报价。删除遮盖区不会删除已加入的商品；更换底图会清除原底图的遮盖区。

单页 PDF 不弹预览或确认窗口，直接导入；多页 PDF 只选择页码。新建项目的模板下拉框包含「已上传的底图／PDF 页面」，可选择已上传页面，无须重新上传。

PDF 自动导入会提取商品图、识别文字并重建商品组件；无法识别的页面保留手动框选。原页面按长边 4000 像素保存供对照。导入后请确认纸张尺寸和清晰度；旧日期及活动条款仍需更新。

底图与新建模板选项按图片内容去重；重复上传同一 PDF 页面会复用已有底图。同名但不同内容保留为不同版本。


### PDF 自动提取、OCR 与商品重建

上传 PDF 时，选定页会调用 `/api/poster-pdf/rebuild`：提取独立 RGB/CMYK 商品图并合成透明蒙版，按位置和重叠关系分组，优先读取原生文字；转曲文字使用 Tesseract 繁体中文＋英文 OCR。重建后的图片、名称、规格、原价、促销价格属于普通商品组件，可以单独选中、修改和替换。组合价格按识别出的“总价／件数”写入，不以四舍五入后的单价反推总价。所有 OCR 商品需勾选核对后才能确认导出，修改名称或报价后会重新要求核对。

单页直接处理，多页只选页码。处理后仍先填写活动信息，再进入商品编辑。编辑页展示提取数量、识别原文和原页对照入口。删除了“旧海报／空白底图”的手动判断选项。保存、恢复或复用已重建项目不再重复识别；新上传的 PDF 运行同一套通用流程。

目前针对常见的商品图片在上、文案和报价在下的零售海报。不是任意 PDF 的完整图层编辑器：页眉、Logo、活动条款仍保留在原底图；商品区用取样底色清理，复杂纹理、角标可能需人工修正。整页扫描件或没有独立商品图时明确提示并保留手动框选；旋转页和过于复杂的分组拒绝自动重建。OCR 存在误读，不保证文字、价格或分组完全准确。

本次需要 `docker compose up -d --build` 同时更新前后端：后端新增 PyMuPDF 及 `tesseract-ocr`、`tesseract-ocr-chi-tra`、`tesseract-ocr-eng`。本机未装 OCR 引擎时会明确报错，不会伪造识别内容。相关接口依据 [PyMuPDF 图片提取](https://pymupdf.readthedocs.io/en/latest/recipes-images.html) 和 [Tesseract TSV 输出](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html)。


### 框选后只换图片或修改旧文字

框选默认「只替换图片」，新放入的图片不显示名称、规格或“待填”价格；若对应已重建商品，只替换图片并保留其原有文字和价格，不新增第二组商品。只有主动选择「替换整组商品」才带入新名称、规格并清空旧报价。既有商品右侧可勾选「只显示图片」，关闭文字展示。

选择「修改旧文字」并输入新内容：若框选到已有可编辑商品字段，直接更新该字段；底图中尚未拆出的文字则由遮盖区覆盖，并新建独立文字层，套用后可调字号、颜色和位置。遮盖颜色可从底图取色。只修改底图文字也可在完成活动资料和核对后导出，不强制添加带价格的商品。

### 全自動換商品（舊海報 PDF＋活動表，可選 Azure 視覺模型）

入口：底圖頁「全自動換商品（舊海報＋活動表）」。上傳舊海報 PDF（可選頁）與活動表（與「Excel 匯入」同一格式；自動流程最多 30 件，以容納 A2 等大海報，一般 Excel 匯入仍為 12 件）。預覽中可「＋ 新增商品」直接補充商品，商品數改變時自動重新分格。系統會：

1. **偵測商品格**：沿用 PDF 重建的商品分組，但跳過舊文字 OCR（名稱和價格改由活動表提供）；逐格測出舊文字區塊（左上角、右邊界）、字號、行距、字重、顏色，以及舊價格牌的墨跡範圍與顏色。
2. **按格號對應、可修改**：商品格按「左上到右下」（先行後列）編號，活動表第 1、2、3… 件依序放入。預覽只顯示格號與新商品；名稱、規格、優惠總價、件數、原價可直接修改，商品可刪除，檢查規則與商品組件相同。
   - 商品數＝格數：逐格替換，沿用原位置。
   - 商品數≠格數（含刪除後）：遮蓋全部舊商品，在原商品區按商品數重新分格（如 7 件為 3＋3＋1 置中、12 件為 4×3），每格沿用代表格的圖片、名稱區、價格牌比例，文字與價格牌按格子大小等比縮放（最多放大 1.4 倍）。
3. **產生新項目**：每格用底色遮蓋舊商品，放入至優價版式的商品卡；文字位置沿用舊海報，字號、行距取全海報中位數，英數用 Arial。價格牌按舊牌尺寸重建；新舊價格類型不同（單一價 ↔「平均每件＋$xx/2件」）時改用同海報該類價格牌的典型尺寸。名稱、規格、價格、件數、原價**只取自活動表**。
   - **空白底圖（全自動）**：上傳 PNG／JPG，或沒有商品格的 PDF，即當作空白底圖。系統找出底圖上大小相近的純色方框（已印好的商品框，按格號放入；框數固定，多出的商品不放入、不足時留空），否則取最大的純色區域作商品區，按商品數分格。都找不到時，若已設定 AI 則由 AI 指出商品區；圖上已有商品則停止並提示改用手動套版。版式沿用 360HK 海報量得的比例（圖片 66%、名稱區、單一價／組合價價格牌、字高約格高 3.4%），文字與價格牌顏色按底色自動取對比色。
   - **商品格偵測**：以紅色價格牌（大號紅色數字）定位，每行價格牌數＝商品數，格子平均分或在價格牌右側結束，左右邊界取底板實際邊緣；遮蓋色取整格最常見的顏色。照片高度參差（如 A2 3＋5＋5＋5）時仍能正確分格。
   - **單一商品 POP**（如「一買即換 +$39」）：找出大號價格、PDF 內嵌的商品相片及左側名稱區，只遮蓋這三處，保留標籤、「+」號、條款與邊框；只放入第 1 件商品。
   - **沿用已保存的底圖與模板**：對話框的「海報來源」列出項目內所有底圖及內建模板（至優價、清爽版、會員八格、感謝祭），預設目前項目的底圖，不必再上傳。用「上傳底圖或舊海報」上傳的 PDF 會連同頁碼保存在本機瀏覽器（IndexedDB），之後選該底圖即沿用原 PDF。
   - **只有圖片的舊海報**：從圖片找價格牌（大號紅色數字＋`$`，且左側有幾行深色名稱文字，以排除標題、標語及包裝上的數字），按價格牌分行分格；單品 POP 則取下半部的大號價格及其上方名稱區。
4. **抠圖**：產生後先看排版，再按畫布工具列的「一鍵抠圖（N 件）」：逐件提交抠圖任務並直接換入商品組件，不必逐件確認；已透明底的略過，同一原圖抠過的直接沿用；失敗的可再按一次重試。結果在素材庫標記「自動抠圖待確認」。單件仍可用素材庫的抠圖按鈕逐件確認。
5. **AI 校對（可選）**：把成品圖與每格應有內容交給視覺模型，列出價格不符、文字溢出、殘留舊價等問題；結果僅供參考，仍需人工核對。

AI 視覺模型的呼叫方式參照 `telecom_recognize_no_mssql`（`AzureOpenAI`、JSON 模式、自動退回不支援的參數、修復常見 JSON 錯誤）。模型名稱只是設定，換模型只改 `AZURE_OPENAI_DEPLOYMENT`。在 `.env` 加入：

```
AZURE_OPENAI_ENDPOINT=https://<資源名稱>.openai.azure.com/
AZURE_OPENAI_API_KEY=<密鑰>
AZURE_OPENAI_DEPLOYMENT=gpt-6.1-sol
AZURE_OPENAI_API_VERSION=2024-12-01-preview
```

未設定時，自動換商品照常運作，只略過「AI 確認商品格」與「AI 校對」。AI 只回傳格子編號、是否為商品及校對意見，不會產生或修改任何商品資料。後端介面：`GET /api/poster-auto/status`、`POST /api/poster-auto/analyze?page=1&ai=1`（PDF）、`POST /api/poster-auto/analyze-image?ai=1`（空白底圖 PNG／JPG／WebP）、`POST /api/poster-auto/review`（JSON）。

PDF 重建同時改為每頁只解析一次原生文字（原本每個文字區各解析整頁一次），向量圖較多的海報由約 65 秒縮短到約 10 秒。

## POS productid 與掛載圖片庫

Excel 支援以 `productid` 查詢 SQL Server 的商品名稱、編號及 B 類條碼，再匹配街貨／倉貨圖片。唯一匹配自動顯示，多圖須選擇；匯入時保存選中圖片快照。部署步驟見 [商品圖片庫部署](docs/product-library.md)。
